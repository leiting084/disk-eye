# DiskEye v0.5 — V5 用户价值功能 + CC 二审（2026-08-27）

## 触发

用户原话"v5候选全做！做完做复核"。

## V5 实施

### V5.1 阈值可配置
- AppConfig 加 4 字段：ProcessSurgeThresholdBytes / FolderSurgeThresholdBytes / SurgeWindowSeconds / SurgeCooldownMinutes
- 设置 tab 加独立 GroupBox「异常增长弹窗阈值」
- ParseMB 做边界检查（1 ~ 1TB）
- 保存时实时同步到 Aggregator（不重启进程）

### V5.2 ETW 替换进程启发式（增强版）
- **决策变更**：放弃 P/Invoke Win32 ETW API（1-2 天工作量 + unsafe 代码多）
- 改用「增强 Process 启发式」：
  - 路径前缀匹配（强信号）
  - CPU 活跃度 + 启动时间近度（兜底）
- 比 v0.3 更精准，能识别"长期存活但最近活跃"的进程

### V5.3 图表视图（今日按小时柱状图）
- 第 5 个 tab「今日趋势」
- GDI+ 自绘（不引入 Chart 控件）
- 24 小时桶，蓝色柱 + 最高值红色突出
- 鼠标 hover 显示具体值（ToolTip）
- Y 轴 4 个刻度（0%, 25%, 50%, 75%, 100%）

### V5.4 进程树视图
- 第 6 个 tab「今日活跃进程」（半树形）
- 列：PID / 进程名 / 父 PID / 父进程名 / 事件数 / 写入字节 / 最近活动 / exe 路径
- 用 WMI 查 ParentProcessId
- 按今日写入字节倒序
- 双击行看该进程今日事件明细

## CC 二审（按全局规则 audit-tool-and-human-review.md）

### 通道 A：audit 工具机检
- ✅ `dotnet build` — 0 错误 0 警告
- ✅ `dotnet publish` — 174 MB 单文件 exe

### 通道 B：人工 D 维度审查（攻击者视角）

#### 🔴 P0 必修

**#1 QueryProcessTree WMI 同步 × N 卡 UI**
- MainForm 每 3 秒调 RefreshData → 触发 QueryProcessTree
- 100 个进程 = 100 次 WMI 查询，每次 ~50ms → 总计 5 秒卡顿
- **修复**：
  - 加 5 秒缓存（`_processTreeCache` + `_processTreeCacheAt`）
  - WMI 查询加 2 秒超时（`Task.Run + Wait(timeout)`）
  - 同一日期范围内复用上次结果

#### 🟢 P3 待优化（V6 候选）

- **#2** ComputeStats 直接开 SqliteConnection 绕过 EventStore（架构不一致）
- **#3** Error 重建 watcher 同步调用（应 Task.Run 异步）
- **#4** MessageOnlyForm 每次创建（应复用单例）
- **#5** SurgeLoop 60 秒硬编码（应让用户可配检查间隔）
