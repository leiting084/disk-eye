## CC 审查发现（按攻击者视角）

### 🔴 P0 必修

**#5 数据库升级兼容性 bug**：
- v0.1 → v0.2 升级时 ALTER TABLE 加了 folder 列，旧数据的 folder 是空字符串
- QueryFolderSummary 用 `folder != ''` 过滤 → **旧事件不出现在文件夹重灾区**
- 用户场景：跑了一周 v0.1，升级 v0.2 后历史文件夹统计丢失
- **修复**：后台任务 BackfillFolderColumn 用 SQL 字符串函数批量回填（1000 条/批，幂等 `WHERE folder = ''`）

### 🟡 P1 必修

**#7 FileSystemWatcher buffer 溢出丢事件**：
- 64KB buffer 在下载 1000+ 文件 / 编译大项目时会溢出
- 原 Error handler 只 log 不恢复 → **永久丢事件**
- **修复**：
  - buffer 翻 4 倍：64KB → 256KB
  - Error 时自动 `Dispose()` 旧 watcher + 调 `CreateWatcher()` 重建

### 🟢 P3 锦上添花

**#8 TopFoldersPopupForm 双击行解析脆弱**：ListBox 文本拼接解析路径容易错。本次**未修**（低优，文本已能用）。

**#10 SQLite 读写并发**：WAL 模式下读不阻塞写、读不阻塞写、写之间由 `_writeLock` 串行化。**OK 无需改**。

**#14 FirstRunForm 关掉不点确定** → MonitoredDrives 为空，下次启动再引导。**有意行为，不修**。

## V3 用户价值功能：路径白名单/黑名单

### 设计
- `AppConfig` 加 `IgnorePrefixes` + `IncludePrefixes` 两个 `List<string>`
- `PathFilterHolder` 静态类持有当前过滤配置（FileSystemWatcherMonitor.Emit 时访问）
- `MonitorService.Start()` 时从配置同步到 holder
- 设置界面加 2 个 TextBox（白名单 + 黑名单）
- 保存时同时写 config.json 和 PathFilterHolder（**立即生效**，不重启）

### 匹配规则
- 黑名单命中即忽略（最高优先级）
- 白名单**非空**时只放行白名单内的路径；空集合=不限
- 路径比较用 `OrdinalIgnoreCase`

### 静态类 vs 依赖注入
用 `PathFilterHolder.Current` 静态属性 + `PathFilter` DTO — 是因为 FileSystemWatcherMonitor.Emit 是高频路径，每次构造注入会导致依赖图复杂度。静态 holder 是务实选择，代价是单测更难（V4 改）。
