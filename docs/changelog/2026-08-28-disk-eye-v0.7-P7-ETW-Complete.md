### 通道 B：人工 D 维度审查（攻击者视角）

#### 🔴 **P0 必修 — EVENT_RECORD 结构错位**

**问题**：原 V7.1 的 `EVENT_RECORD` struct 定义**字段顺序错**：
- `EventDescriptor` 我当成 `EVENT_RECORD` 的字段，但实际 Win32 它**在 EVENT_HEADER 内部**
- `EVENT_HEADER` 漏掉了 `EventDescriptor` + `ProcessorTime`，所以大小**实际 40 字节 vs 真实 64 字节**
- 所有 `Marshal.PtrToStructure` 读出的 `ProcessId` / `ProviderId` / `EventId` 全部**错位的内存**

**影响**：ETW 看似启用成功（IsActive=true），但反查的 PID 全部是错误的内存值。用户只会看到"反查结果怪怪的"，不会想到是结构错位。

**修复**：改用 `Marshal.ReadInt32/ReadInt16 + Marshal.Copy` 按 Win32 文档固定偏移读：
```csharp
// 0-7: Size/HeaderType/Flags/EventProperty (8 字节)
// 8-11: ThreadId (4 字节)
// 12-15: ProcessId ← 关键
// 16-23: TimeStamp (8 字节)
// 24-39: ProviderId (GUID 16 字节)
// 40-55: EventDescriptor (16 字节, 含 Id at 40)
// 56-63: ProcessorTime (ulong)
// 64-65: UserDataLength (ushort)
// 66-67: UserDataOffset (ushort)
```

修复后偏移**严格按 Win32 文档**，避开 .NET struct padding 问题。
