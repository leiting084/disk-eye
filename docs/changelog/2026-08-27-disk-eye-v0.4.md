## V4.1 数据导出 CSV

### 实现
- `EventStore.ExportToCsv(path, since?)` — 用 SqlDataReader 流式读取，UTF-8 + BOM 编码
- 列：`id,time,drive,folder,event,size_bytes,process_name,pid,full_path,exe_path`
- 含 folder 列（V2 的文件夹重灾区数据也带出）
- MainForm 工具 tab 2 个按钮：
  - **导出全部事件到 CSV…**（带 SaveFileDialog，默认桌面）
  - **导出今日事件**（简化：since=今天 00:00）
- 导出成功后自动 `explorer.exe /select,<path>` 选中文件
- 含 CsvEscape 处理（含逗号/引号/换行的字段用双引号包裹）

### 关键设计
- 不在内存里加载全表 → SqlDataReader 流式，100万行也不会 OOM
- BOM 加在 StreamWriter 顶部 → Excel 直接打开不乱码

## V4.2 异常增长弹窗

### 设计
- `EventAggregator.SurgeAlert` 事件
- 后台 `SurgeDetectLoop` 每 60 秒检查一次（独立 CancellationToken，与 PumpLoop 隔离）
- 检查逻辑：
  - 进程维度：某进程在窗口期（默认 1 分钟）内总 size > **100MB** → 弹通知
  - 文件夹维度：某文件夹 > **500MB** → 弹通知
- 同一进程/文件夹 30 分钟冷却（防轰炸）
- 每分钟最多弹 1 个（避免通知堆叠）

### 阈值可覆盖
- `Aggregator.ProcessSurgeThresholdBytes` 默认 100 MB
- `Aggregator.FolderSurgeThresholdBytes` 默认 500 MB
- `Aggregator.SurgeWindow` 默认 1 分钟
- `Aggregator.SurgeCooldown` 默认 30 分钟

### UI 反馈
- Windows 气泡通知（`NotifyIcon.ShowBalloonTip`，8 秒超时，Warning 图标）
- 标题：「DiskEye — 进程突增」/「DiskEye — 文件夹突增」
- 正文：`{key} 在 60s 内写了 100 MB (1234 个文件)`

### 关键决策
- **阈值要够"高"才不打扰**：100MB/分钟对普通用户是 10 倍正常水平，避免被 IDE 编译、git clone 误触发
- **同 key 冷却 30 分钟**：避免某下载器持续触发，每次弹窗
- **每分钟最多 1 个**：避免多进程同时飙导致通知轰炸

## 用户场景示例

```
19:23  vmware.exe 在 60s 内写了 850 MB (12 个文件)        ← V4.2 弹通知
19:24  [用户打开主窗]  看到凶手指控榜 → vmware.exe 占据第一行
        → 双击行查看详细事件 → 双击文件夹打开资源管理器 → 删掉那 12 个临时文件

[或者]
20:05  用户点「导出全部事件到 CSV」 → 文件保存到桌面 DiskEye-all-20260827-200500.csv
     → 用 Excel 打开 → 按 size_bytes 排序 → 找出大文件源头
```
