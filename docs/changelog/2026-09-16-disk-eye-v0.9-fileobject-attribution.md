# DiskEye v0.9.0 — ETW FileObject 状态机归因（2026-09-16）

## 用户问题

v0.8.1 的"凶手指控榜"大面积失真。对 publish_v81 真实库（events.db，727,006 行，08-29~09-15）的实测：

| 指标（2026-09-14） | 数值 |
|---|---|
| 全天 unknown 率 | **59.9%**（419k/700k），开机 5 分钟风暴内爬到 82% |
| 空闲底盘 unknown（08:34 后每分钟仅 ~15 事件）| 仍稳定 10–36% |
| 空闲期 unknown Modified 中同路径早先存在具名事件的比例 | **92%** |
| 事件 size=0 的比例 | 91% |
| 心跳"今日新增" | +148 GB（文件当前大小快照重复累加，非真实写入）|

## 根因（全部经 etw-probe 实测，非推测）

1. **模型缺陷**：只消费 FileIo/Create(ID12)（仅"打开"瞬间）+ 主进程 4 秒 TTL 路径缓存。长句柄写入者（SQLite WAL、浏览器、日志）4 秒后永久失联。
2. **风暴饱和**：子进程对每个事件同步 `Process.GetProcessById` + stdout 逐行 AutoFlush；2,600+ 事件/秒时 EV 延迟超过 3 秒匹配窗口。
3. **覆盖缺口**：删除/改名不消费；目录属性 Modified（单个 Temp 路径占空闲 unknown 的 73%）照入库。
4. **fallback 摆设**：启发式 BestByPrefix 用 exe **文件全路径**对被写文件做 StartsWith，几乎不可能命中。
5. **字节口径错误**：真实写入在 FileIo/Write(ID16)，从未消费。

## 方案

归因模型升级为 **ETW FileObject 句柄状态机为权威源，FSW 退为生命周期通知**：

- 子进程回调线程只做固定偏移解析 + `HandleStateTable`（FileObject→pid/路径，句柄存活期恒定）+ 有界非阻塞帧队列；`Process.GetProcessById` 全部移到异步 `PidNameResolver`；写字节 1 秒聚合（短命句柄在 Cleanup 时冲刷残留字节）。
- V1 帧协议（首行版本号）：OP/WR/CL/DL/RN/NM/ST，主进程 `AttributionEngine` 维护 path→writer/opener 属主 + 30 分钟 recent LRU + 删除帧 + 改名迁移 + 目录集合；未命中短等 1 秒，超时 pending 入库、属主晚到 10 秒内回填。
- 真实写入字节入新表 `write_bytes`（榜单/今日/图表/异常增长统一口径，不再累加 FileInfo 快照）；新增 `attribution_ab_hourly` 做 v1/v2 每小时对照。
- 目录属性事件不入库；启发式改用 exe **所在目录**前缀 + System32/Program Files 等公共目录降权。
- 保留 v0.8.1 已验证的单 exe 双角色、子进程隔离、看门狗、60 秒冷却重启、孤儿 session 自清理；config `AttributionEngineV2=false` 可回退；ETW 死亡时零阻塞降级，字节暂停并在 UI 明确标识。

## 实测踩坑（已固化为单测 fixture，防回归）

- ID16 Write 的 **FileObject 在 offset16**（Create/Delete 在 offset8）；初稿按 8 取导致 OnWrite 全 miss（countWrite=0），靠"ID12 off8 == ID16 off16"交叉测试抓出。
- 写字节数在 **offset36 uint32**（12345/100000/777 逐字节命中；初稿误记 28）；删除 disposition 在 **offset24=1**（非 20）。
- CreateOptions 的目录位不可靠（普通打开目录时为 0），目录改以 **NT 路径尾反斜杠**判定。
- 短命句柄（1 秒聚合窗内写+关）字节在 Cleanup 冲刷，否则整文件字节丢失。

## 验证

- xunit **65 个全绿**（FrameProtocol/HandleStateTable/AttributionEngine/KernelFileParser 用真实捕获字节/BoundedFrameWriter/启发式前缀）。
- `experiments/e2e-attribution/run_e2e.py` 对 Debug 与发布版均 **8/8 PASS**：
  write_bytes 精确 == 1,163,122（12345+100000+1000000+50000+777）、8 秒长句柄正确归因 python.exe、删除/改名具名、
  生命周期事件与有写入文件零 unknown。
- 杀子进程后主程序即时降级（startup.log 可见），60 秒后自动恢复。
- 已知残留：少量无对应 FileObject 帧的元数据型 Modified（系统 lazy-writer 刷元数据的重复通知）保持 pending；
  它们不影响 write_bytes 与生命周期归因，风暴指标见 attribution_ab_hourly。

## 交付与回退

- `publish_v90/DiskEye.exe`（单文件自包含 196MB，仍是一个 exe + `--etw-child`）。
- 回退：config.json 设 `"AttributionEngineV2": false`（子进程协议不变，主进程退化为 4 秒 create-only v1 行为）；`"EnableEtw": false` 彻底关 ETW。
- 3 天 A/B 观察：`experiments/e2e-attribution/`（runbook 见 spec）；目标白天具名率 ≥90%（对照 v0.8.1 全天 59.9%）。
