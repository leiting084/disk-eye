# DiskEye v0.1 — MVP 完成（2026-08-27）

## 背景

用户硬盘突然变满，想知道哪个进程干的。急用，需要桌面托盘工具。

## 设计决策（用户已批准）

- 追溯精度：B（中级模式 — 反查父进程）
- 监控范围：B（指定盘符，可运行时切换）
- 历史保留：C（永久保留 + 30 天自动归档）
- 技术栈：C# .NET 8 + WinForms + FileSystemWatcher + SQLite

## 实现

- **监控核心**：`FileSystemWatcher` 每盘符一个 watcher（递归），事件入 `ConcurrentQueue`
- **反查进程**：`Process.GetProcesses()` 启发式匹配（每 2 秒刷缓存）
  - 策略1：路径前缀匹配（路径在哪个进程 exe 的目录下 → 该进程）
  - 策略2：启动时间接近度匹配（事件前后 10 秒内启动的进程）
  - V2 计划：换 ETW Kernel-File provider 拿精确 pid
- **存储**：SQLite WAL 模式；`events` 活跃表 + `events_archive` 归档表
- **聚合**：`EventAggregator` 100ms 批量入库
- **UI**：
  - 托盘（自动生成的眼睛图标，避免依赖 .ico 文件）
  - `MainForm` 三 tab：凶手指控榜（默认）+ 事件流 + 设置
  - `FirstRunForm` 首次引导选盘符 + 自启动
- **凶手指控榜 SQL**：`SELECT process_name, COUNT(*), SUM(size), MAX(ts) FROM events WHERE ts>=today GROUP BY process_name ORDER BY SUM(size) DESC`
- **单实例**：Mutex + NamedPipe（双击=显示已有窗）
- **自启动**：HKCU\...\Run 注册表（无 admin）
- **包大小**：单文件自包含 173 MB（含 .NET 8 运行时 + SQLite 原生库）

## 反哺经验

1. **Microsoft.Diagnostics.Tracing.TraceEvent API 复杂**：3.1.x 版的 `EnableProvider` 重载签名不可预期（编译错误信息指不到正确重载），放弃了 ETW 路线 → 改用 `Process` 启发式。如果未来需要 ETW，建议用 P/Invoke `EtwEnableTraceEx2` 直接调 Win32 API。
2. **yield + catch 不能共存**：C# 5+ 仍然禁止。把 yield 移出 try-catch 即可。
3. **ApplicationContext.Exit 是 protected**：不要在 lambda 里直接 `Exit += handler`，要 override `OnExit` 方法。
4. **KeyValuePair 没有 `.Id` 字段**：用 `.Key` 和 `.Value`。
5. **WinForms NotifyIcon 需要 Icon 对象**：为了避免引入 .ico 二进制，运行时用 `Bitmap.GetHicon()` + `Icon.FromHandle` 程序化生成图标。⚠️ 必须 `DeleteObject(hicon)` 否则 GDI 句柄泄漏。
