# DiskEye v0.9.11 — DPI 裁字修复 + 切盘即时生效 + C 盘回归监控（2026-09-17）

## 用户反馈 → 处置（3 条）

| 反馈 | 根因 | 处置 |
|---|---|---|
| "搜索按钮/状态栏文字展示一半" | **DPI 裁字**：Form 未设 AutoScaleMode，9pt 字在 150% 缩放下渲染变高，固定高度控件（按钮 28/状态条 24）装不下 | Form `AutoScaleMode=Font`；按钮 AutoSize+MinimumSize；状态条高度跟随 Label 实测高（SizeChanged 联动） |
| "凶手指控榜跟 C/D 设置无关" | 榜单按"今天"聚合：**切走盘符不清其历史字节**，旧数据挂着像没生效 | UpdateConfig（含托盘勾选/设置保存）时 PurgeWritesOutsideDrives——切走即清，立即反映 |
| "设置了 C 盘也不出 C 文件夹" | **config 实际是 ["D"]**——设置 tab 勾选后必须点"保存设置"才生效（托盘菜单勾选才是即时的）；且勾选后 C 数据从那一刻起积累，不会回溯 | config 已加回 C；验证新实例 C+D 双盘流动（C: telemetry/.cc-switch/Temp 新积累中） |

## 顺带回答（上一轮 1/2）

- "乱码" = Rust/Cargo `target\debug\deps\` 哈希命名中间产物 exe（如 todolist_lib-ad6a40e03a21678e.exe）+ claude.exe.old.* 升级残留——合法文件名。v0.9.9 起 >34 字符中段截断显示。
- "未知——进程已退出且未抓到 exe" = 写入真实但进程已退出（短命进程）。v0.9.9 加 pid→exe 档案（进程启动必开自己 exe 的 OP 帧），已验证 cargo/rc.exe/build-script-build 等短命进程现在有完整路径。
