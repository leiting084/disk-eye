## 步骤 1：版本命名统一（用户痛点）

**问题**：之前 v0.5（5 个版本）和 V5（5 个功能阶段）共用同一数字空间"5"，任何人都会混淆。

**解决**（CLAUDE.md 已加命名约定）：

| 类型 | 格式 | 例 | 用途 |
|------|------|------|------|
| 版本号 | `v<major>.<minor>` | v0.1 → v0.6 → v1.0 | 对外（用户看到的）|
| Phase 编号 | `P<n>` | P1-MVP / P6-ETW | 对内（开发阶段）|

**对照表**（在 CLAUDE.md 也写）：

| 版本 | Phase | 主要内容 |
|------|-------|---------|
| v0.1 | P1 MVP | 基础监控 + 凶手指控榜 |
| v0.2 | P2 | 文件夹重灾区 + 托盘 Top10 |
| v0.3 | P3 CC | buffer 翻倍 + 白/黑名单 |
| v0.4 | P4 Surge | CSV + 弹窗 |
| v0.5 | P5 Visualization | 阈值 + 图表 + 进程树 |
| v0.6 | P6 ETW | P/Invoke 框架 + P3 优化 + 搜索框 + 自启延迟 |

## 步骤 2：V6 候选全部实施

### V6.1 P/Invoke Win32 ETW（占位实现）
- `EtwWin32Provider.cs`：P/Invoke `EtwStartTrace` + `EtwEnableTraceEx2` 启用 `Microsoft-Windows-Kernel-File`
- 状态：**仅启用 provider，未做事件解析**（`OpenTrace` + `ProcessTrace` + `EVENT_RECORD` 解析需要 unsafe 代码 + MOF 字段映射，工作量大）
- 实际反查仍走 `EtwProcessResolver` 增强版（V5.2 已实现）
- **V7 计划**：完整实现事件解析 + (path → pid) 滑动窗口

### V6.2 P3 性能优化（4 项全做）
- **#2 ComputeStats 移到 EventStore**（架构一致性）— `EventStore.GetStats() : DbStats`
- **#3 Error 重建 watcher 异步化**（Task.Run，避免阻塞 Error 事件分发）
- **#4 MessageOnlyForm 复用单例**（GC 压力）
- **#5 SurgeLoop 检查间隔可配**（响应 SurgeWindowSeconds 变化，下限 5 秒上限 10 分钟）

### V6.3 顶栏搜索框
- MainForm 顶部加 TextBox（带 placeholder + debounce 300ms）
- 跨 4 个 tab 过滤（凶手指控榜 / 文件夹 / 事件流 / 进程树）
- "清空" 按钮 + 大小写不敏感

### V6.4 自启延迟 30 秒
- `Program.cs` 解析 `--delay N` 参数（0-600 秒边界检查）
- 注册表项写入 `--minimized --delay 30`
- 避免开机时和系统 IO 抢资源
