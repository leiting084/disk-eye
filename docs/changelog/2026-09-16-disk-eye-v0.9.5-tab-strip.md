# DiskEye v0.9.5 — tab 标签条可见性修复（V6.3 布局遗留）+ 字节口径说明（2026-09-16）

## 现象

用户持续反馈"7 个 tab 看不到"。v0.9.4 已确认窗口置顶可见、榜单有数据，但截图放大后实锤：
**标题栏下面直接是搜索栏和表格，中间没有 tab 标签条**。

## 根因（Win32 EnumChildWindows 布局证据）

```
Window.8   (pnlSearch 容器)  rect=847x24 @620,267
SysTabControl32 (TabControl) rect=847x571 @620,267   ← 与搜索栏同 y，重叠！
```

V6.3 加顶栏搜索框时 `_pnlSearch.BringToFront()` 把搜索栏置于 Z 序顶。
WinForms Dock 布局按 **z-order 从底向顶** 处理：TabControl（z 底）先布局 Fill 占满整个客户区
（含标签条），搜索栏（z 顶）后布局 Top 覆盖顶部 36px——**TabControl 的标签条（约 22px 高）
被不透明搜索栏完全盖住**。7 个 tab 一直都在且可点区域存在，但标签永远不可见。
从 V6.3 起即如此，非 v0.9 引入。

## 修复

BuildUI 末尾 `_tabs.BringToFront()`（移除旧 `_pnlSearch.BringToFront()`）：
TabControl 到 z 顶、最后布局，拿到"扣掉搜索栏 36px"的剩余空间，标签条露出。

## 写入字节口径（用户问"记录的磁盘大小是真实的么"）

- **真实**：write_bytes 来自内核 ETW FileIo/Write（offset36 字节数，逐字节实测验证），
  是"该进程向磁盘写入的数据量"的精确记账，归因与数值真实。
- **口径=逻辑写入量 ≠ 硬盘占用增量**：缓存/延迟落盘/日志反复写/杀软回写均计入；
  压缩与稀疏文件逻辑字节大于实占。对照任务管理器"磁盘写入"列量级一致。
- events.size 列为文件当前大小快照，仅明细展示，不参与总量（列头已标"文件大小"）。
